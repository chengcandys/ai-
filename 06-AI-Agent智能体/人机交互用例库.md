# 用例库 · 人机交互（15 个协作场景）

> 模式原理见 [人机交互与协作用例](./人机交互与协作用例.md)。每个用例给出：**场景 → 人机分工档位 → 交互设计 → 教训**。

## 一、开发与工程

### 用例 1：AI 结对编程（计划确认 + diff 审批）
- **档位**：审批模式（关键动作审批 + 其余自治）
- **交互设计**：Agent 先出实现计划待人批准 → 分步实现，每步给出 diff → 危险命令（删除类、push）单独审批 → 人 review 后合并
- **教训**：把审批点放在"计划"和"diff"上，比逐行盯代码高效 10 倍

### 用例 2：线上事故应急（建议模式 + 一键执行）
- **档位**：建议模式（Agent 只读诊断，人执行修复）
- **交互设计**：Agent 实时输出根因假设 + 证据 + 建议命令 → 人点"采纳"才执行 → 执行结果回流给 Agent 继续分析
- **教训**：高压场景下"人按按钮"比"人敲命令"更快更少错，但按钮必须显示影响面与回滚方式

### 用例 3：数据库变更（强审批 + 双人复核）
- **档位**：审批模式（不可逆操作）
- **交互设计**：Agent 生成迁移脚本 → 展示"影响行数 / 锁表时长 / 回滚脚本"→ 人工审批（必要时双人）→ 灰度执行 + 实时监控
- **教训**：审批界面不给"影响预估"= 逼人盲目点同意

### 用例 4：新人代码上手（共驾模式）
- **档位**：Copilot 辅助（人主导，AI 解释）
- **交互设计**：新人问"这个函数做什么"→ Agent 结合仓库上下文解释 + 指出调用方 → 新人自己改，AI 只做审查提示
- **教训**：定位是"加速理解"而非"代替写"，否则新人永远长不大

## 二、内容与创意

### 用例 5：文案创作（建议模式）
- **档位**：建议模式（AI 出多方案，人选）
- **交互设计**：一次给 3 个不同风格的草稿 + 各自的受众定位 → 人选一个 → 针对性迭代 → 人定稿
- **教训**：给选择比给"唯一答案"更受欢迎；3 个选项是甜蜜点（多了选择疲劳）

### 用例 6：设计稿生成（共驾）
- **档位**：共驾（AI 生成初稿，人精修）
- **交互设计**：人给品牌规范 → AI 出 5 版构图 → 人选定 → 局部重绘（img2img / ControlNet 锁构图）
- **教训**：可控性（局部改、锁构图）比"一次生成完美"重要得多

### 用例 7：视频成片（流水线 + 关键点审批）
- **档位**：流水线自治 + 两次审批
- **交互设计**：脚本 AI 生成 → **人审脚本**（花 5 分钟省 2 小时返工）→ AI 配音/配图/剪辑 → **人审成片**
- **教训**：把审批放在"最贵返工点"的前一步

### 用例 8：数据报告（异步委托 + 存疑标注）
- **档位**：异步委托（人布置后离开）
- **交互设计**：Agent 产出报告 + 明确列出"需要人复核的 3 个数据存疑点" + 每个数字可下钻来源
- **教训**：交"带置信度标注的成果"而非"看似确定的答案"

## 三、企业与服务

### 用例 9：智能客服（档位分层 + 升级转交）
- **档位**：L1 自治（FAQ）→ L2 审批（退款等敏感诉求）→ L3 人工（升级）
- **交互设计**：转人工时自动附对话摘要 + 已尝试方案 + 用户情绪标签，人不用从零问
- **教训**：升级交接质量决定"人机协同"的真实效率，否则人只是重新做一遍

### 用例 10：销售线索跟进（监督模式 + 抽检）
- **档位**：监督模式（Agent 自动触达，人抽检）
- **交互设计**：Agent 按策略发消息（话术模板 + 个性化变量）→ 高风险话术（报价、承诺）需审批 → 每日抽检 5% 对话 + 看板指标
- **教训**：面向客户的动作必须有"话术红线白名单"，不能全靠模型自觉

### 用例 11：HR 面试安排与初筛（建议 + 人工终审）
- **档位**：建议模式（AI 排序 + 理由，人定）
- **交互设计**：AI 出候选人排序 + 匹配理由 + 明显不匹配原因 → HR 复核 → 涉歧视性条件自动屏蔽
- **教训**：涉及人的评价必须可解释、可申诉，且最终决定权在人

### 用例 12：政务/银行窗口助手（辅助模式）
- **档位**：Copilot 辅助（工作人员用，非直接面向民众）
- **交互设计**：工作人员提问"这项业务的办理材料"→ AI 依据规章制度答 + 给出条款原文链接 → 人向民众解释
- **教训**：高风险领域"AI 辅助专业人士"比"AI 直接面对用户"落地阻力小得多

## 四、个人与学习

### 用例 13：学习陪练（苏格拉底式，共驾）
- **档位**：共驾（AI 不直接给答案）
- **交互设计**：AI 只提问引导 + 指出思路漏洞 → 学习者自己得出结论 → AI 出题检验
- **教训**：直接给答案会让学习失效；"不代劳"本身需要写进系统提示

### 用例 14：个人知识库助手（建议 + 引用）
- **档位**：建议模式（RAG 带引用）
- **交互设计**：每次回答附来源块 → 找不到依据时明确说"知识库中没有" → 支持人一键纠错回流
- **教训**：个人场景最怕"一本正经胡说"——宁可拒答也不要编

### 用例 15：日程与任务管家（异步委托 + 审批）
- **档位**：委托（低风险自治）+ 审批（对外动作）
- **交互设计**：Agent 自动整理待办、起草回复 → **发邮件/改会议**类对外动作需人确认 → 每日晨间简报
- **教训**：区分"内部整理"（自主）与"对外代表我"（审批）——这是个人 Agent 的信任底线

## 通用设计经验（15 个用例的共性）

1. **审批点放在"最贵返工点"和"不可逆动作"前**，不要在无关紧要处打断人
2. **审批请求三件套**：要做什么 + 为什么 + 影响/回滚方式（缺失即盲目批准）
3. **档位分层而非一刀切**：同一系统里只读自治、写入审批、对外人工
4. **升级/转交必须带完整上下文**：否则"人机协同"退化成"人重做一遍"
5. **给选择而非给唯一答案**：3 个候选 + 理由，是最受欢迎的交互形态
6. **宁可拒答不要编造**：高风险场景的可信度 > 覆盖率
7. **渐进放权**：先建议 → 再审批 → 再监督 → 最后自治，用真实运行数据换信任

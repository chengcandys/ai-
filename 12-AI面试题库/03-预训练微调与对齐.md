# 03 · 预训练、微调与对齐（20 题）

## 预训练

### Q1. LLM 训练的三个阶段及各阶段目标？
1. **预训练 Pretrain**：海量无标注文本自监督学习"预测下一个 token" → 获得语言能力与知识
2. **监督微调 SFT**：用高质量指令-回答数据微调 → 学会按指令对话
3. **偏好对齐 RLHF/DPO**：用人类偏好数据进一步对齐 → 更有帮助、更无害、更诚实

### Q2. 预训练数据如何治理？
- 来源配比：网页、书籍、代码、论文、对话（代码数据提升推理能力）
- 清洗：去重（MinHash/语义去重）、过滤低质（分类器/规则）、去毒（隐私/有害内容）
- 加分点：数据质量 > 数据数量，"garbage in garbage out"；课程式数据排布（先易后难）

### Q3. 什么是灾难性遗忘？如何缓解？
- 微调时在新任务上学好了，却忘记预训练的通用能力
- 缓解：混入通用数据回放（Replay）、低学习率、只训部分参数（LoRA 天然缓解）、正则约束偏离原模型

### Q4. 继续预训练（Continual Pretrain）与直接 SFT 的区别？
- 领域适配顺序：先领域语料继续预训练（学知识）→ 再 SFT（学指令格式）
- 领域数据少时直接 SFT 容易过拟合、知识注入有限

### Q5. 训练大模型需要多少算力？怎么估算？
- 经典估算：训练 FLOPs ≈ 6 × 参数量 × token 数（前向 2 + 反向 4）
- 例：7B 模型训 1T token ≈ 4.2×10²² FLOPs
- 面试常配合 Chinchilla 最优配比追问

## 微调

### Q6. 全量微调 vs 参数高效微调（PEFT）？
- 全量：效果上限高，但显存/算力贵、易遗忘
- PEFT：只训 <1% 参数 → 成本低、多任务可挂载多个适配器、天然缓解遗忘
- 选型：数据充足追求极致 → 全量；大多数业务场景 → LoRA 足够

### Q7. LoRA 原理？
- 冻结原权重 W，用低秩分解学增量：ΔW = B·A（B: d×r, A: r×k，r≪d，典型 r=8~64）
- 推理时 W+BA 可合并回原权重，**零额外推理延迟**
- 显存省在：优化器状态只需存小矩阵（全量微调优化器状态约为参数 2 倍）

### Q8. QLoRA 相比 LoRA 的改进？
- 把基座权重量化到 4bit（NF4）冻结，LoRA 适配器仍用 bf16 训练
- 配合双重量化 + 分页优化器 → 单卡 24GB 可微调 65B 模型
- 代价：量化带来轻微精度损失，训练速度略慢

### Q9. LoRA 的 rank、alpha 怎么选？挂在哪些层？
- rank：8~64 常用，任务越复杂越大；过大易过拟合
- alpha/rank 决定缩放强度，一般 alpha = 2×rank
- 挂层：至少 Q/V，效果更好挂全部线性层（Q/K/V/O + FFN）

### Q10. SFT 数据怎么做质量最高？
- 质量三要素：指令多样性、回答正确性、格式一致性
- 数量经验：几千~几万条精标数据常胜百万条噪声数据（LIMA 假说："少即是多"）
- 常见来源：人工标注、强模型蒸馏（需注意许可）、真实业务日志清洗

### Q11. 什么时候该微调、什么时候用 Prompt/RAG？
| 需求 | 方案 |
|------|------|
| 注入新知识/实时数据 | **RAG**（微调学知识不可靠且易幻觉） |
| 改变输出格式/风格/语气 | Prompt 优先，不够再 SFT |
| 教新技能/领域行为模式 | **SFT** |
| 对齐价值观/偏好 | RLHF/DPO |
- 黄金原则：能 Prompt 不 RAG，能 RAG 不微调

## 对齐（Alignment）

### Q12. RLHF 完整流程？
1. 训练奖励模型 RM：同一 prompt 多个回答人工排序 → RM 学打分
2. PPO 强化学习：LLM 生成回答 → RM 打分作为奖励 → 更新策略
3. 加 KL 散度惩罚：防止策略偏离 SFT 模型太远（跑偏/ reward hacking）

### Q13. DPO 相比 RLHF 的改进？
- 不需要单独训练奖励模型、不需要 RL 采样，直接用偏好对（chosen/rejected）做类似分类的训练
- 优势：简单稳定、成本低、效果接近 RLHF → 开源社区主流
- 变体：IPO、KTO（只需单条好/坏标注）、ORPO

### Q14. Reward Hacking 是什么？怎么防？
- 模型学会"讨好"奖励模型而非真正变好（如回答变长、堆砌好词）
- 对策：KL 约束、多奖励模型集成、定期人工抽检、奖励模型持续迭代

### Q15. RLHF 后的模型为什么变"懒"/保守（Alignment Tax）？
- 对齐税：安全与有用性存在张力，过度对齐导致拒绝率升高、能力下降
- 平衡：更好的偏好数据配比、 constitutional AI（原则自评）等方法

### Q16. GRPO 是什么？（DeepSeek-R1 带火）
- PPO 需要 Value 模型（显存翻倍）；GRPO 用**同组多个回答的相对得分**估计优势，去掉 Value 模型
- 配合规则化奖励（答案对不对可自动判分：数学/代码）→ 大规模 RL 训练推理能力

### Q17. 推理模型是如何训练出来的（R1 路径）？
- Base → 少量冷启动 CoT 数据 SFT → 大规模 RL（GRPO + 可验证奖励）→ 涌现长思维链、自我反思（"aha moment"）
- 蒸馏：把 R1 的长链推理数据蒸馏给小模型，小模型推理能力大幅提升

### Q18. 模型评估怎么做？
- 通用榜单：MMLU、HumanEval（代码）、MATH、GPQA
- 中文：C-Eval、CMMLU
- 业务侧：构建自有评测集 + LLM-as-Judge（用强模型打分）+ 人工抽检
- 陷阱：榜单过拟合/数据污染（训练集泄露进评测集）

### Q19. 什么是数据污染（Contamination）？如何检测？
- 评测集出现在训练语料里 → 分数虚高
- 检测：n-gram 重叠分析、改写题面后性能骤降检测、使用新出的动态评测集

### Q20. 模型"对齐"还包含哪些安全维度？
- 有害内容拒答、越狱攻击防御（Jailbreak）、提示注入防御、隐私泄露防护
- 红队测试（Red Teaming）：上线前系统性地攻击自己的模型找漏洞
- 加分点：提到《生成式 AI 服务管理暂行办法》等合规要求（国内岗位）

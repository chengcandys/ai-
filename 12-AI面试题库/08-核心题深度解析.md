## 深度解析 1：Transformer 为什么能取代 RNN？（开场题，定基调）

**标准答案三层递进**：

1. **计算层面**：RNN 按时间步串行（$h_t$ 依赖 $h_{t-1}$），无法并行 → GPU 利用率低；注意力对全序列并行计算，训练吞吐量差一个数量级，这是 Scaling 的前提。
2. **梯度层面**：RNN 梯度经 $L$ 步连乘 $\prod \frac{\partial h_t}{\partial h_{t-1}}$，步数多了必然消失/爆炸，长距离依赖学不到；注意力中任意两 token 直接相连，梯度路径长度恒为 1。
3. **表达层面**：多头注意力让不同子空间学不同关系（句法/指代/位置），FFN 提供逐位置非线性加工，残差+归一化保证深层可堆叠。

**追问链**：为什么解码器要掩码 → 为什么除 √d_k → O(n²) 怎么解（FlashAttention/稀疏/滑窗）→ 既然 RNN 串行慢，为什么 Mamba/SSM 又火回来（线性复杂度 + 选择性状态空间，长序列推理成本优势）。

**满分要点**：答到"梯度路径长度为 1"和"并行是 Scaling 的前提"两个关键词，表明你理解的是本质不是结论。

## 深度解析 2：自注意力手撕（含完整推导）

$$Q=xW_Q,\ K=xW_K,\ V=xW_V;\qquad \text{Attn}=\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}+M\right)V$$

- 维度：`x[B,L,D]` → `Q,K,V[B,H,L,d_k]` → 分数 `[B,H,L,L]` → 输出 `[B,L,D]`
- 缩放推导：设 q、k 各分量独立零均值单位方差，则 $q\cdot k$ 的方差为 $d_k$ → 除 $\sqrt{d_k}$ 使方差归 1，softmax 不饱和
- 掩码：上三角置 -inf，softmax 后对应权重为 0
- 常见扣分点：忘了 `contiguous().view()`、掩码方向写反、dk 与 D 混用

**追问**：MHA→GQA 省什么？——KV Cache 从 $2\cdot L\cdot D\cdot N_{layer}$ 降到按 K/V 头数计，Llama3-8B（32 头→8 KV 头）Cache 直降 4 倍。

## 深度解析 3：RoPE 为什么成为主流位置编码？

1. **机制**：Q/K 两两维度视为复数，按位置 m 旋转 $e^{im\theta_i}$，$\theta_i$ 随维度指数衰减（高频维度转得快）
2. **相对性**：$\langle f(q,m), f(k,n)\rangle = g(q, k, m-n)$ —— 内积只依赖相对距离，这正是语言需要的
3. **外推性**：可配合位置插值（PI）、NTK-aware（高频少压低频多压）、YaRN（分段+温度）把 4K 窗口扩到 128K+
4. **对比**：绝对位置编码（sin-cos/可学习）外推必崩；ALiBi 外推最强但表达略弱、无旋转的远距离衰减先验单一

**追问**：长窗口的代价？——Prefill O(L²)、KV Cache O(L)、Lost in the Middle；工程上"扩窗"和"长文本继续预训练"必须配套。

## 深度解析 4：LoRA 的原理、显存账与调参

**原理**：冻结 $W_0 \in \mathbb{R}^{d\times k}$，学 $\Delta W = BA$，$B\in\mathbb{R}^{d\times r}$、$A\in\mathbb{R}^{r\times k}$，前向 $y = W_0x + \frac{\alpha}{r}BAx$。

**显存账（7B 模型 bf16）**：
- 权重 14GB（冻结，不算梯度）；
- 全量微调另需：梯度 14GB + Adam 一阶二阶动量（FP32）56GB ≈ 84GB+ → 单卡无望
- LoRA（r=16，挂全线性层，~0.3% 参数）：可训参数 ~20M → 梯度+优化器状态 <1GB，单卡 24GB 可训

**调参经验**：r=8~64；alpha=2r；学习率比全量高一个量级（1e-4 vs 1e-5）；任务越接近预训练分布，r 可越小。

**追问**：LoRA 为什么天然抗灾难性遗忘？——原权重冻结，通用能力无损；增量被限制在低秩子空间，扰动小。QLoRA 怎么再省？——基座 NF4 量化到 4bit 冻结，反量化参与前向。

## 深度解析 5：RLHF 全流程与 DPO 的等价视角

**RLHF 三步**：SFT → 奖励模型（pairwise 排序损失 $-\log\sigma(r_{chosen}-r_{rejected})$）→ PPO（目标 = RM 奖励 $-\beta\cdot D_{KL}(\pi \| \pi_{SFT})$）。

**三个必答坑**：
1. Reward Hacking：策略钻 RM 空子（变长、堆词）→ KL 约束 + RM 迭代
2. PPO 四模型同驻显存（Actor/Critic/RM/Ref）→ 成本极高
3. 在线采样 → 吞吐瓶颈

**DPO**：利用闭式解把"奖励-策略"关系代入，得到直接在偏好对上的分类损失；免 RM、免采样、免 Critic。**代价**：离线数据分布偏移敏感、对偏好数据质量更挑。

**GRPO**：组内 G 个采样的平均奖励当基线替代 Critic，配合可验证奖励（数学答案对/代码过测试）→ R1 的关键工程创新。

**满分要点**：能写出 PPO 目标式 + 说清"KL 项防跑偏"+ 三方法在"奖励来源"上的本质差异。

## 深度解析 6：幻觉的成因分类与全链路治理

**分类**（答出分类学即加分）：
- 事实性幻觉：与世界知识矛盾（记错了）
- 忠实性幻觉：与输入/检索内容矛盾（没照着答）
- 成因链：数据噪声与长尾缺失 → 最大似然训练鼓励"像人话"而非"说真话" → 自回归误差累积 → 对齐阶段若惩罚"我不知道"会逼模型硬答

**治理按链路**：
| 环节 | 手段 |
|------|------|
| 数据 | 清洗、去重、知识密集配比 |
| 训练 | 诚实对齐（奖励拒答不确定性）、RAG 化训练 |
| 推理 | 低温、RAG、引用强制 |
| 后验 | NLI 校验、LLM 自核、一致性投票（Self-Consistency） |

**量化话术模板**："我们通过引用强制 + 低相似度拒答兜底，把抽检幻觉率从 30% 降到 12%，代价是拒答率上升 5%。"

## 深度解析 7：向量检索的工程细节（RAG 必考）

**为什么余弦不用欧氏**：模长受文本长度/置信度影响，余弦只比方向，语义检索更稳；embedding 归一化后余弦 ≡ 点积，可用内积索引加速。

**ANN 三兄弟**：
- **HNSW**：分层小世界图，查询跳表式逼近 → 召回率 95%+、延迟最低、内存最大；核心参数 M（每点边数）、ef_construction/ef_search；Milvus 默认
- **IVF**：先聚类 nlist 个簇，查询只搜 nprobe 个簇 → 内存省，召回靠 nprobe 调
- **PQ**：向量分段量化压缩 8~32 倍 → 亿级以上必配，精度有损 → 常与 IVF 组合（IVF-PQ）

**追问**：亿级向量怎么做？——IVF-PQ + GPU 索引 + 分片；千毫秒预算内召回。

## 深度解析 8：混合检索与 RRF（生产标配）

**纯向量三大短板**：精确匹配差（"RFC 7231"）、专业术语召回差、专有名词易丢 → 补 BM25（词频-逆文档频率精确匹配）。

**RRF 融合公式**：
$$\text{RRF}(d) = \sum_{i} \frac{1}{k + \text{rank}_i(d)},\quad k \approx 60$$

- 只用排名不用分数 → 免疫两路分数量纲差异，比手动加权（向量 0.7/BM25 0.3）稳健，生产首选

**Rerank 两阶段架构**：Bi-Encoder 粗排（双塔分别编码，可预计算，快但交互浅）→ Cross-Encoder 精排（query+doc 拼接过模型，准但慢不可预计算）→ **检索 Top-20 → Rerank 取 Top-5**。

**量化数据（可引用）**：加 Rerank 后 Top-5 召回 71%→89%，Top-3 准确率 65%→84%。

## 深度解析 9：Chunk 切分的决策框架

**权衡**：大了信息稀释（相似度被拉低），小了上下文断裂（断章取义）。

**生产配方**：递归切分（段落→句子→字符优先级）chunk_size≈500 中文字、overlap 10~20%（约 100 字）；按文档类型定制：Markdown 按标题层级、代码按函数/类、FAQ 一问一答不可拆、表格转 Markdown 整表保留。

**进阶三件套**：
1. Parent-Child：小块检索、命中返回父块（精确 + 上下文兼得）
2. 上下文扩展：命中块前后各带一块
3. 元数据过滤：chunk 携带文档/章节/权限标签，检索前置过滤

## 深度解析 10：RAG 效果差怎么排查？（闭环思维展示题）

**按归因矩阵逐层定位**（先测后改）：

| 现象 | 归因 | 对策 |
|------|------|------|
| 答案块根本不在 Top-K | 检索层 | 查切分/embedding/混合检索/查询改写 |
| 在 Top-K 但 Rerank 后被刷掉 | 精排层 | 换 Rerank 模型、调候选数 |
| 在上下文里但没被使用 | 生成层 | Prompt 强调引用、位置前移（防 Lost in the Middle）、换更强模型 |
| 用了但答错/编造 | 忠实度 | 低温、逐句引用、NLI 校验 |

**关键动作**：先建 50~100 条"问题→标准答案块"评测集，分层打指标（Recall@K / MRR / Faithfulness），**没有评测集不谈优化**。

## 深度解析 11：Agent 与 Workflow 的分界（2026 高频新题）

**本质区别**：控制权在谁手里。Workflow 在代码（流程写死，LLM 是节点处理器）；Agent 在 LLM（自主规划下一步）。

**量化对比**：Agent token 消耗约为 Workflow 的 **4~8 倍**；Workflow 可预测、易调试；Agent 灵活但漂移风险高。

**满分答案**：生产主流是**混合架构**——Workflow 提供稳定骨架（确定性主链路），Agent 处理分支与异常（开放性子任务），高风险节点人工审批。举例：客服系统 80% 简单问题走 Workflow，复杂问题升级 Agent，投诉转人工。

**追问**：怎么判断任务该用哪种？——看"路径可枚举性"：步骤能预先枚举的用 Workflow，依赖中间结果动态决策的用 Agent。

## 深度解析 12：ReAct 的防死循环与成本控制

**ReAct 循环**：Thought→Action→Observation；优点透明可审计，缺点 token 大、可能死循环、延迟高。

**防死循环三招**（必须背出）：
1. **最大步数限制**（常用 15 步，超限强制总结退出）
2. **重复动作检测**（连续 3 次相同 tool+args → 判定卡死，换策略或退出）
3. **超时控制**（墙钟上限）

**成本对照**：Plan-and-Execute 的 token 消耗约为 ReAct 的 **20%**（规划一次 vs 每步全上下文思考）→ 简单固定任务优先 Plan 模式或 Workflow。

**追问**：Reflection 模式适用场景？——质量优先于成本的任务（代码生成、法律文书）：生成 Agent + 评审 Agent 迭代；也可用于幻觉自校正。

## 深度解析 13：Function Calling / MCP / Skills / A2A 四层体系

**一句话定位**：Skills 决定"怎么想"→ MCP 决定"用什么"→ Function Call 决定"怎么调"→ A2A 决定"和谁协作"。

| 层 | 解决问题 | 技术本质 |
|----|----------|----------|
| Function Call | LLM 表达调用意图（LLM 自己不执行！） | API 协议（JSON Schema） |
| MCP | 工具接入标准化，N×M → N+M | 通信标准（JSON-RPC 2.0，stdio / HTTP+SSE） |
| Skills | 领域方法论编码（审查标准、工作流程） | 按需注入的提示词资产（trigger 激活） |
| A2A | Agent ↔ Agent 横向协作（Agent Card/Task/Artifact） | HTTP+JSON+SSE，Google 推动 |

**关键认知**：Function Call 解决"何时调、传什么参"；MCP 的 `tools/list` 实现运行时**动态发现**工具无需重新部署；Skills vs Few-shot——Few-shot 教格式，Skills 教方法论；MCP 纵向（Agent↔工具），A2A 横向（Agent↔Agent），互补不替代。

## 深度解析 14：生产环境 Agent 五大坑与解法（工程实战题）

| 坑 | 表现 | 解法 |
|----|------|------|
| 死循环 | 反复调同一工具 | 最大步数 + 重复动作检测 + 超时 |
| 幻觉工具调用 | 调不存在的工具/编造参数 | 工具名严格校验、schema 强约束、非法调用直接报错回喂 |
| 上下文污染 | 无关历史干扰当前任务 | 任务边界重置会话、结构化状态快照 |
| Token 爆炸 | 工具返回 MB 级数据 | 输出截断 + 分页 + 摘要回传 |
| Prompt Injection | 检索/网页内容夹带恶意指令 | 数据/指令分离、内容标记包裹、高危操作人工审批 |

**配套可靠性设计**：工具幂等、写操作可回滚、降级链（主工具→备用→明确失败）、全量 Trace 审计。

## 深度解析 15：设计一个企业级 Agent 系统（压轴系统设计题）

**五维答题框架**（面试直接套）：

1. **工作模式**：主链路 Workflow 保底 + 开放子任务 Agent（ReAct/Plan 混合）；防死循环三招
2. **工具管理**：MCP 统一接入、权限分级（只读放行/写需审批）、工具检索动态加载、调用审计
3. **记忆与状态**：短期上下文（Auto-Compact 压缩）+ 任务状态（Redis）+ 长期记忆（向量库）；写什么/何时读/如何遗忘
4. **可靠性与安全**：幂等回滚、降级熔断、Injection 防御、最小权限、Human-in-the-Loop
5. **可观测与成本**：完整 Trace 回放、token 预算与告警、模型路由（简单任务小模型）、缓存（工具结果/Prompt Cache）、轨迹评估回归集

**收尾金句**："模型能力趋同后，Agent 系统的竞争力在 Harness 工程——上下文治理、状态管理、评测闭环。"

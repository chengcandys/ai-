# 01 · 模型与架构对比

> 每张表最后一列"结论/建议"是可直接引用的选型判断。

## 1. 序列建模架构四代对比

| 维度 | RNN/LSTM | CNN（1D卷积） | Transformer | SSM/Mamba |
|------|----------|---------------|-------------|-----------|
| 并行性 | 差（时序串行） | 好 | 好 | 好（训练并行） |
| 长依赖 | 差（梯度衰减） | 中（感受野有限） | 强（直接连接） | 强（状态传递） |
| 推理复杂度 | O(n) | O(n) | **O(n²) 训练 / O(n) 推理带KV Cache** | O(n) |
| 长序列成本 | 中 | 低 | **高（KV Cache 线性增长）** | 低（常数状态） |
| 生态与效果 | 老旧 | 一般 | **最好（事实标准）** | 追赶中 |
| **结论** | 教学与轻量时序任务 | 局部模式/轻量场景 | **默认选择** | 超长序列/端侧探索阶段，不建议生产押注 |

**反思**：RNN 被淘汰不是"效果差"，而是**无法并行 → 无法 Scaling**。判断技术前途时，"能否吃到算力红利"往往比当下的效果更重要。

## 2. 注意力变体对比

| 变体 | KV Cache 大小 | 质量 | 解码速度 | 用在哪 |
|------|---------------|------|----------|--------|
| MHA 多头 | 100% | 最好 | 基准 | 早期模型 |
| MQA 多查询 | ~1/H | 略降 | 最快 | 大模型推理优化 |
| **GQA 分组查询** | ~1/G | **接近 MHA** | 快 | **Llama2/3、Qwen 主流** |
| MLA 多头潜在 | 压缩后很小 | 好 | 中 | DeepSeek 系 |

**结论**：新模型设计直接上 GQA；面试被问"推理优化从哪下手"，KV Cache 是第一顺位。

## 3. 位置编码对比

| 方案 | 相对性 | 外推能力 | 代价 | 采用者 |
|------|--------|----------|------|--------|
| 绝对（可学习/sin-cos） | 无 | 弱 | 无 | 早期 BERT/GPT |
| ALiBi | 隐含（线性偏置） | 最强（免微调） | 表达略弱 | BLOOM 等 |
| **RoPE** | 天然相对 | 强（配插值可扩到 128K+） | 需调插值参数 | **几乎全部主流 LLM** |

**结论**：RoPE + 插值（NTK/YaRN）是扩窗事实标准；面试重点答"为什么要位置编码"（自注意力本身置换不变）。

## 4. 归一化与激活对比

| 项 | 选项 | 结论 |
|----|------|------|
| 归一化位置 | Post-Norm vs **Pre-Norm** | 深网必须 Pre-Norm（梯度通路） |
| 归一化方式 | LayerNorm vs **RMSNorm** | RMSNorm 省算力、效果相当 → 主流 |
| 激活 | ReLU / GELU / **SwiGLU** | 大模型用 SwiGLU（门控 + 收敛快） |
| BN vs LN | BN 依赖 batch；LN 与 batch 无关 | NLP/Transformer 用 LN；CNN 可用 BN |

## 5. 微调方案对比（成本-效果-适用）

| 方案 | 可训参数 | 显存（7B 级） | 效果上限 | 灾难性遗忘风险 | 适用 |
|------|----------|---------------|----------|----------------|------|
| 提示词（不改模型） | 0 | - | 取决于模型 | 无 | **首选验证** |
| RAG（不改模型） | 0 | - | 知识注入强 | 无 | 动态/私有知识 |
| LoRA | ~0.1~1% | 单卡 24G | 高 | 低 | **业务微调主力** |
| QLoRA | 同上（4bit 基座） | 更低 | 略降 | 低 | 硬件受限 |
| 全量微调 | 100% | 多卡 | 最高 | 高 | 数据充足 + 深度定制 |
| 继续预训练 | 100% | 多卡 | 领域知识最强 | 高 | 领域语料海量（百亿 token 级） |

**结论**：默认从 Prompt 起，知识走 RAG，行为走 LoRA；不要用微调解决"知识更新"问题（会加剧幻觉）。

## 6. 对齐方法对比

| 方法 | 需要奖励模型 | 需要在线采样 | 稳定性 | 成本 | 现状 |
|------|--------------|--------------|--------|------|------|
| RLHF（PPO） | 是 | 是 | 差（需调） | 高（4 模型同驻） | 大厂对齐标配 |
| **DPO** | 否 | 否 | 好 | 低 | 开源社区主流 |
| GRPO | 否（规则奖励可自动判分） | 是（组内采样） | 中 | 中 | **训推理能力主力（R1）** |
| SFT 冷启动 | - | - | - | 低 | 任何对齐前的必经步骤 |

## 7. 主流模型选型矩阵

| 场景 | 首选类型 | 理由 |
|------|----------|------|
| 通用对话/复杂推理 | 顶级闭源 API（GPT/Claude/Gemini） | 能力上限高，省运维 |
| 成本敏感批量任务 | 国产 API（DeepSeek/Qwen/GLM） | 性价比高，中文好，无需特殊网络 |
| 数据不出域 | 开源模型自部署（Qwen/DeepSeek/Llama） | 私有化 + 可微调 |
| 离线/端侧 | 小模型 + Ollama/llama.cpp | 隐私 + 零边际成本 |
| 数学/代码推理 | 推理模型（R1/o 系） | 思维链 + Test-time Scaling |
| 超长文档 | 长上下文模型 + RAG 混合 | 单靠长窗口成本高、利用率低 |

> 模型格局以"季度"为单位变化，**这张表每季度用 web-search-free 核实一次**（时效核实原则）。

## 反思：架构层面的三个常见误区

1. **"新架构一定更好"**——Mamba/SSM 有优势但生态、工具链、效果验证尚不成熟；生产押注要看"是否已被大规模验证"
2. **"参数量越大越强"**——Chinchilla 后是"数据配比 + 后训练质量"的竞争；7B 精调可胜 70B 裸模型（特定任务）
3. **"架构是核心竞争力"**——开源趋同后（Decoder-only + RoPE + SwiGLU + GQA），**数据配方与训练工程**才是壁垒

# 14 · 技术对比与选型（横向总结 + 反思）

> 前面 13 个目录按"知识线"纵向组织；本篇按"决策线"横向对比，回答 **"A 和 B 该选哪个、为什么、什么时候选错"**。这是从"学过"到"会用"的关键一跃。

## 为什么单独建一个对比板块

- 单章讲技术 A 时天然只说 A 的优点；**只有横向放在一起，trade-off 才显形**
- 面试与实战的真正难点不是"知不知道有 RAG"，而是"这个需求该不该用 RAG"
- 技术会过时，但**对比维度与判断框架长期有效**

## 使用方法

1. **决策前查**：遇到"该选什么"的问题，先查对应对比表的"结论"列
2. **面试前扫**：对比表本身就是最好的面试速答素材（trade-off 是加分项）
3. **每季度复盘**：技术对比表的"当前推荐"会变——变动项就是要重学的部分

## 三条通用判断原则（比具体结论更重要）

1. **没有最好的技术，只有最合适的约束**——先问清约束（成本/延迟/数据/团队能力），再谈选型
2. **简单方案优先，按需升级**——Prompt → RAG → 微调；单 Agent → 多 Agent；Workflow → Agent
3. **为演进留后门**——抽象接口隔离模型/向量库/框架，让"换掉它"的成本足够低（技术会变，此原则不变）

## 学完自测检查点

1. 任意抽 3 组对比，能说出"什么情况下选 A、什么情况下选 B"（而非"A 更好"）
2. 说出被淘汰技术（如 RNN 做长文本、纯向量检索）的失败原因，并归纳共性问题
3. 用"约束优先"原则为一个假想需求做完整选型推演
4. 记住三条通用原则，并能各举一个自己踩过的反例

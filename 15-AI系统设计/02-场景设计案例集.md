# 02 · 场景设计案例集（8 个高频 AI 系统设计题）

> 每个案例按五步法展开：**需求澄清 → 容量估算 → 架构 → 核心设计（灵魂问题）→ 权衡与演进**。架构通用部分见 [01 篇](./01-通用架构蓝图与容量估算.md)，此处只写场景特有设计。

---

## 案例 1：ChatGPT 式通用对话系统

**需求**：多轮对话、流式输出、上下文记忆、千万级用户。
**容量**：参考 [01 篇 §2.2](./01-通用架构蓝图与容量估算.md) 方法；关键是**会话级并发**而非请求级（长连接资源）。
**架构**：接入（WebSocket/SSE 长连接 + 会话路由）→ 编排（上下文组装）→ 模型网关 → 数据层（会话状态 Redis + 历史 PG）。

**核心设计（三个灵魂问题）**：
1. **上下文管理**：历史无限增长 vs 窗口有限 → 分层策略（最近 N 轮原文 + 早期摘要 + 关键事实卡片），超限触发 Auto-Compact
2. **流式输出**：SSE 逐 token 推送 + 断线重连（Last-Event-ID 续传）；取消按钮必须能真正终止推理（省 token）
3. **会话状态**：写扩散——每轮结束异步落库；读路径 Redis 优先，冷启动 PG 回源

**权衡**：长记忆（体验）vs 成本（每轮 token）→ 记忆摘要化；一致性（多端同步）用"服务端会话为唯一事实源"。

## 案例 2：企业知识库问答（RAG 系统）

**需求**：万级文档、员工按权限问答、答案可溯源、文档日更。
**架构**：离线 Pipeline（解析→切分→Embedding→入库）+ 在线链路（查询改写→混合检索→Rerank→生成带引用）。

**核心设计**：
1. **权限过滤**：检索时用 metadata filter 前置过滤（部门/密级），**绝不能生成后再遮**（已泄露进上下文）
2. **文档更新**：增量索引（变更文档重切分重嵌入 + 旧向量删除）+ 版本字段；embedding 模型升级 = 全量重建（双写切换零停机）
3. **答案可信**：逐句引用编号 + 相似度阈值兜底（低于阈值答"未找到"）+ 点踩回流 badcase 库

**权衡**：索引实时性 vs 成本（实时双写 vs 日级批量）；GraphRAG 只在有全局性问题时引入（成本 5~20 倍）。
**演进**：MVP（向量+引用）→ V2（混合检索+Rerank）→ V3（Agentic 多库路由）。

## 案例 3：智能客服系统

**需求**：7×24、解决率优先、敏感操作（退款）需人工、对接工单系统。
**架构**：意图路由（小模型分类）→ 三层应答（FAQ 缓存直答 → RAG 生成 → 转人工）→ 工具层（订单/物流查询 MCP）。

**核心设计**：
1. **解决率 vs 风险的分层**：L1 FAQ（高置信直出）；L2 RAG（附引用+置信度）；L3 敏感动作（HITL 审批）；L4 转人工（带对话摘要+已尝试方案）
2. **情绪识别**：用户情绪负面 → 提前转人工（体验红线）
3. **护栏**：话术白名单（不承诺无依据的赔偿）、越界问题拒答并引导
4. **闭环**：未解决会话每日聚类 → 补充 FAQ/知识库 → 评测集回归

**容量要点**：语义缓存命中率是成本命门（FAQ 类可达 40%+）；高峰期模型降级链（主→备→缓存→模板）。
**权衡**：转人工率高=成本高但满意度高；解决率与满意度要双看板，不能只顾一个。

## 案例 4：AI 编程助手（IDE 内）

**需求**：代码补全（毫秒级）、对话式编程（秒级）、代码库问答、自动修 bug。
**架构**：双通道——**补全通道**（小模型+FIM，<300ms）与**对话通道**（Agent+工具）；代码索引层（符号表+AST+增量更新）。

**核心设计**：
1. **补全延迟**：小模型 + 推测解码 + 本地缓存；上下文只取"当前文件+打开的标签+最近编辑"（不索引全库）
2. **代码检索为什么不用纯 RAG**：符号精确匹配（Grep/AST 索引）+ 语义检索混合；代码高频变更，向量索引滞后 → 实时索引（文件监听+增量更新）
3. **安全边界**：危险命令审批、沙箱跑测试、diff 必须人审
4. **上下文工程**：仓库地图（repo map 压缩表示）让模型"知道"全库结构而不读全库

**权衡**：补全质量（大模型）vs 延迟（小模型）→ 分级：Tab 补全小模型、块生成大模型。

## 案例 5：AI 内容审核平台

**需求**：UGC 文本/图片审核，日均亿级，误杀率与漏放率双控。
**架构**：多级漏斗——规则/黑名单（毫秒，拦 60%）→ 小模型分类（快速，拦 30%）→ 大模型精审（疑难 10%）→ 人工复审（<1%）。

**核心设计**：
1. **漏斗经济**：每一级成本升 10 倍、量降 10 倍——大模型只审"拿不准的"（不确定性采样）
2. **多视角投票**：规则视角+语义视角+上下文视角，2/3 通过才放行（提置信）
3. **对抗性内容**：变体词/谐音/图片嵌入文字 → 归一化预处理 + 持续对抗样本回流训练
4. **申诉闭环**：误杀申诉 → 人工复审 → 样本回流 → 阈值调整（周级迭代）

**权衡**：误杀伤用户体验 vs 漏放伤平台安全——按内容分级定阈值（涉政/未成年人零容忍，广告类可宽松）。

## 案例 6：多模态内容生成平台（文生图/视频）

**需求**：高并发生成请求、生成时长 10s~5min、按次计费、内容合规。
**架构**：**异步任务队列为核心**——接入（提交任务）→ 队列（优先级调度）→ GPU Worker 池（弹性伸缩）→ 审核（生成后机审）→ 存储 CDN → 回调/轮询通知。

**核心设计**：
1. **异步架构**：同步等生成 = 连接资源耗尽；提交即返 job_id，SSE/Webhook 推送进度（排队中→生成中→审核中→完成）
2. **GPU 调度**：按显存需求装箱（文生图/视频不同池）、冷热模型分离（热门模型常驻、长尾按需加载）、Spot 实例降本
3. **成本与限额**：按次/按分辨率阶梯计费；每用户并发与每日配额限制；失败自动重试（不计费）
4. **合规**：提示词过滤（输入）+ 生成结果机审（输出）+ 水印/标识（AIGC 合规要求）

**权衡**：排队时长（体验）vs GPU 利用率（成本）→ 峰谷预测性扩容 + 低峰跑批量任务填谷。

## 案例 7：实时语音助手（端到端语音对话）

**需求**：语音进语音出、延迟 <1s、可打断、多轮上下文。
**架构**：两条路线对比选型（核心设计 1）→ 流式管道（ASR 流→LLM 流→TTS 流）→ VAD 打断检测 → 会话管理。

**核心设计**：
1. **三段式 vs 端到端**：
   - 三段式（ASR→LLM→TTS）：可控、便宜、可插拔，但延迟累加（1.5~3s）、丢失语气
   - 端到端（音频 token 直进直出）：延迟 <1s、能理解情绪、自然打断，但贵、可控性弱
   - **选型**：客服/工具类用三段式（要可控），陪伴/交互类用端到端（要体验）
2. **打断（Barge-in）**：VAD 检测到人声 → 立即停 TTS + 丢弃 LLM 未发送流 + 保存上下文断点
3. **全双工流式**：三段各自流式 + 管道并行（ASR 出半句就喂 LLM，LLM 出短语就喂 TTS）
4. **状态同步**：打断后文本与音频的上下文对齐（用户听到的才算数）

**权衡**：延迟每降 100ms，工程复杂度上一个台阶——先三段式跑通，再逐步替换为端到端。

## 案例 8：搜索 + LLM 混合系统（AI 搜索 / 答案引擎）

**需求**：自然语言提问，返回带来源的整合答案（Perplexity 类产品）。
**架构**：查询理解（改写+拆解）→ 搜索引擎 API（多路）→ 网页抓取与清洗 → 重排 → LLM 整合生成（逐句引用）→ 缓存。

**核心设计**：
1. **查询理解是灵魂**：多轮指代消解、子问题拆解（复杂问题拆 2~4 个并行搜索）、时效判断（"最新"→ 强制按时间排序源）
2. **抓取质量控制**：主内容提取（去广告/导航）、反爬与超时降级、来源权威性加权（官方 > 媒体 > UGC）
3. **引用准确性**：答案句与来源段落的对应校验（NLI）——引用错配是此类产品的头号质量事故
4. **成本**：搜索 API 调用 + 抓取 + 长上下文整合三层成本 → 语义缓存（相同意图命中）+ 热点预生成

**权衡**：答案详尽（更多源+更长上下文=更贵更慢）vs 简洁 → 按查询类型分流（事实类简短，调研类出长报告）。

## 八案横向速查

| 案例 | 灵魂问题 | 第一优先级 |
|------|----------|-----------|
| 对话系统 | 上下文管理 | 流式体验 |
| 知识库问答 | 权限与溯源 | 检索质量 |
| 智能客服 | 解决率 vs 风险 | 分层+闭环 |
| 编程助手 | 延迟分级 | 上下文工程 |
| 内容审核 | 误杀/漏放双控 | 漏斗经济 |
| 生成平台 | 异步与 GPU 调度 | 任务队列 |
| 语音助手 | 端到端选型 | 打断处理 |
| AI 搜索 | 查询理解 | 引用准确性 |

**通用启示**：8 个案例用了同一套六层架构，差异全在"编排层的场景逻辑"和"数据层的场景数据"——**架构是可复用的，场景理解是不可替代的**。

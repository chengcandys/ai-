# 15 · AI 系统设计（应用开发者视角）

> 传统系统设计问"怎么扛住百万 QPS"，AI 系统设计多了一层灵魂拷问：**"怎么让一个会犯错、不按量计费按 token 计费、延迟以秒计的概率系统，跑出确定性的业务结果？"** 本板块回答这个问题。

## AI 系统设计 vs 传统系统设计（先建立心智差异）

| 维度 | 传统系统设计 | AI 系统设计 |
|------|--------------|-------------|
| 核心资源 | CPU/内存/IO | **Token 预算 + GPU 显存 + 上下文窗口** |
| 延迟量级 | 毫秒 | **秒级**（LLM 推理）→ 流式与异步成为一等公民 |
| 正确性 | 确定性（测过就对） | **概率性**（测过也可能错）→ 评估与护栏贯穿设计 |
| 成本模型 | 按机器时长 | **按 token/调用量** → 缓存与路由直接决定毛利 |
| 故障模式 | 崩溃/超时 | 幻觉/漂移/注入/成本失控 → 需要"优雅降级"而非"报错" |
| 扩容单位 | 实例数 | 实例数 × **模型层（路由/量化/自托管）** |

**一句话**：传统设计管"流量"，AI 设计还要管"**不确定性**"和"**按量燃烧的钱**"。

## AI 系统设计五步法（每道题的通用答题框架）

```
1. 需求澄清：用户是谁、输入输出什么、容错率多少、合规边界在哪
2. 容量估算：QPS → 每分钟 token 量 → 模型成本/GPU 数量（公式见 01 篇）
3. 架构分层：接入 → 编排 → 模型（网关/路由）→ 数据（RAG/记忆）→ 观测
4. 核心设计：针对该场景的 2~3 个灵魂问题深入（如对话系统=上下文管理）
5. 权衡与演进：自建 vs API、同步 vs 异步、准确率 vs 成本的取舍与迭代路线
```

**面试加分点**：主动说出"容错率决定架构"——容错高的场景（创意）可以激进用 AI，容错低的场景（支付）AI 只能辅助。
